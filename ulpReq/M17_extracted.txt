1. Introduction


1.1 Module purpose

M17 (Accounts) provides accounting infrastructure for ULP tenants. It records financial transactions, manages GL/AR/AP, computes taxes, supports period close, and produces statutory and management reports. As of v2.0, the module is structured as Core + Plugins to support multiple tax regimes.

3.1 Chart of Accounts



    CREATE TABLE m17_account (

      id BIGINT PRIMARY KEY AUTO_INCREMENT,

      tenant_id INT NOT NULL,

      country_code CHAR(2) NOT NULL,             -- NEW v2.0; "IN" for existing

5.1 Invoice state machine



    Draft ──[ready]──▶ PendingApproval ──[approve]──▶ Approved ──[post]──▶ Posted (Issued)

      │                   │                                                    │

      │                   └──[reject]──▶ Draft                                 │

      │                                                                        │

      │                                       ┌──partial──┐                    │

      │                                       ▼           ▼                    │

      │                                PartiallyPaid     Paid ◀────[receive]───┤

      │                                                                        │

      │                                                  Outstanding ──[overdue]

      │                                                                        │

      │                                                                  ──[write-off]──▶ Written-off

      └──[void]──▶ Void (terminal, before posting)



Plugin extension: When invoice transitions to Posted, the active plugin is invoked. M17-IN generates IRN via IRP. M17-US calls Avalara/TaxJar for sales tax. Plugin failures roll the invoice back to Draft with errors.

8. Audit Trail


8.1 Mandate

Indian Companies Act Section 138: audit trail of all transactions, changes, deletions in accounting software is mandatory for Indian companies. M17-Core enforces this universally.



US SOX (for public co): similar audit trail requirements. M17-Core covers both.




8.2 Audit log schema



    CREATE TABLE m17_audit_log (

      id BIGINT PRIMARY KEY AUTO_INCREMENT,

12. M17-IN: India Compliance Plugin


12.1 Scope

M17-IN implements all Indian accounting compliance per the original v1.0 design. Functionality unchanged from v1.0; only repackaged as plugin.




12.2 GST computation
Transaction type
Tax components

Intra-state (same state)

CGST + SGST (each typically half of total rate)

Inter-state (different state / export)

IGST (full rate)

Imports (post-customs)

IGST on assessable value + customs duties

Exports

Zero-rated (with refund) or LUT-based



    // India tax computation (preserved from v1.0)

    public class IndiaTaxProvider : ITaxProvider

    {

        public string CountryCode => "IN";

    

        public async Task<TaxComputeResult> ComputeTaxAsync(

            TaxableTransaction txn, ITenantContext t, CancellationToken ct)

        {

            var hsn = txn.HsnCode;

            var rate = await _gstRates.GetRateAsync(hsn, txn.PostingDate);

    

            var supplierState = await GetSupplierStateAsync(t);

            var recipientState = await GetRecipientStateAsync(txn);

    

            if (supplierState == recipientState) {

                // Intra-state: split CGST + SGST

                var half = rate / 2;

                return TaxComputeResult.Split(

                    cgst: txn.Amount * half / 100m,

                    sgst: txn.Amount * half / 100m);

            } else {

                // Inter-state: IGST

                return TaxComputeResult.IGST(

                    igst: txn.Amount * rate / 100m);

            }

        }

    }




12.3 IRN generation


Triggered on invoice POST event for B2B invoices with value > threshold


Calls IRP API (NIC1, NIC2, IRIS, GSTHero, etc.)


Receives IRN (64-char hash), QR code, signed JSON


Stores IRN on m17in_invoice_ext.irn column


Failed IRN: invoice goes to retry queue; alerts after 3 failures
